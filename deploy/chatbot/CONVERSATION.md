# 로컬 상담과 자동 갱신

- 상담 API는 외부 LLM을 호출하지 않는다. 인사·감사·도움말은 제한된 규칙으로 응답하며, 공고 설명은 승인·해시 검증을 통과한 자료만 사용한다.
- `rag_api.py`는 `rag_dialogue.py`로 질문을 분류하고 기존 `rag_search.py`로 근거를 검색한다. `rag_sync.py`와 `rag_refresh_cycle.py`는 현재 AWS의 승인 자료 갱신 구현이다. 60초 갱신, 승인 확인 만료·변경 차단 정책을 그대로 유지한다. 과거 README의 고정 자료 설명은 초기 버전에 해당한다.
- 대화 정보는 웹페이지 메모리에만 두고 매 요청의 `question` 안에 제한된 참고 문맥으로 전달한다. 지역·관심 작물·경영체 등록 응답은 자기 진술이며 자격 충족 근거가 아니다. 새 대화 또는 페이지 새로고침 시 초기화한다. 서버 DB에는 저장하지 않는다.
- 요청 형식은 기존 `{"question":"질문"}`을 유지한다. 응답은 기존 `answer`, `programs`, `sources`에 `kind`, `conversation`, `suggestions`를 추가한다. 문맥은 열거된 항목만 허용하고, 실제 질문 길이 1,000자 제한·응답 전 승인 재검증을 유지한다.
- 지역 탐색은 해당 지역 관련 공고를 찾는 기능이다. 전국 사업·지역 미확인 자료를 임의로 신청 가능으로 판정하지 않는다. 현재 검증 자료에서 찾지 못한 경우 전체 지원사업이 없다는 뜻으로 안내하지 않는다.
- 원문 발췌와 승인 요약, 확인일, 모집기간 경과·미확인, 미확인 조건을 함께 표시한다. 승인 요약은 최신 원문 전체 검증을 뜻하지 않는다.

## 배포와 복구 범위

기존 운영 API의 `rag_api.py`, 신규 `rag_dialogue.py` 및 웹 파일 `index.html`, `assets/chat-ui.js`, `assets/chat-ui.css`만 교체한다. 기존 systemd 서비스는 코드 로드를 위해 재시작하되, 소켓·네트워크 격리·128MiB 제한·갱신 타이머·Nginx 설정은 변경하지 않는다. API 파일과 웹 파일을 먼저 백업하고, 실패 시 해당 파일만 복원한 뒤 기존 API를 다시 시작한다.

`source-manifest.json`은 공개 코드와 비공개 근거의 무결성 목록이다. 비공개 원문·승인 스냅샷·운영 DB·키는 저장소에 추가하지 않는다. 새 서버에서는 저장소만으로 근거 자료를 재현할 수 없으므로 권한 있는 비공개 배포 자료가 필요하다.

## 자연어 조건 비교

`rag_profile.py`는 제한된 한국어 표현에서 거주지·영농지역·나이·경영체 등록·작물·영농 경력·시작 예정·신청자 유형·단체 인원·시설면적을 추출한다. 모호한 정보와 지원사업 자체의 조건을 사용자 사실로 확정하지 않는다. 현재 나이를 과거 공고 기준일의 나이로 환산하지 않는다. 지역·작물 인식은 등록된 이름 범위의 규칙 기반이며 일반 목적 자연어 모델이 아니다.

검증된 공개 피드 조건의 AND/OR/NOT을 따라 비교하고, 승인 설명문에서는 명시된 단체 최소 인원·시설면적·경영체 등록 요건만 보수적으로 보완한다. 근거 없는 연령·경력 기준일, 거주지와 농지 소재지, 현재 재배와 장래 사용 의무를 서로 대체하지 않는다. 일부 조건이 일치해도 전체 자격 충족으로 표시하지 않는다. 공고 수정·취소와 자료 무결성 검증은 기존 갱신 로더 및 응답 직전 재검증을 유지한다.

추가 대화 필드는 `age`, `age_basis`, `applicant`, `group_size`, `group_min`, `farming_years`, `planned`, `cultivating`, `facility_sqm`, `farm_region`이다. 모든 값은 크기·유형·범위를 제한하고 현재 페이지 메모리에서만 유지한다. 질문 전송 형식과 기존 API 보안·외부 통신 차단은 유지한다. 나이·경력의 기준일, 단체 형태, 등록 작물·교육 예외 등 구조화하지 않은 조건은 추가 확인으로 남긴다.
