# AWS 배포 차단 항목 확인 결과

확인일: 2026-11-18. 시작 커밋: `6f25d81`. 이번 범위는 백업·해시 대조·격리 브라우저 검증이며 코드 배포·Push·승인·수집을 수행하지 않았다.

## 1. 현행 백업과 복원 검증

- 기존 보고의 DB 140건·공개 92건은 이후 예약 수집으로 DB 151건·공개 99건이 됐다. 이번 작업에서 수집하거나 공개 상태를 변경한 결과가 아니다.
- 실제 DB는 `/var/lib/munongsa/monitor.sqlite3`이다. 읽기 전용 연결과 읽기 트랜잭션에서 SQLite 온라인 백업 기능으로 기존 백업과 겹치지 않는 새 비공개 디렉터리에 스냅샷을 생성했다. 실행 중 DB를 파일 복사하지 않았다.
- 전체 11개 테이블을 보존했다. 공고 151건, 승인·검토 이벤트 175건, 자격조건 버전 259건을 포함한다. 원본·백업·별도 복원 DB의 테이블별 행 수와 행 내용 해시가 일치했고 양쪽 `integrity_check`는 `ok`였다.
- 권한·검토 기록 파일, 공개 데이터, 비공개 근거, 배포 대상 기존 코드와 관련 서비스 파일 등 236개 파일도 별도로 보관했다. 별도 복원 디렉터리에 풀어 파일별 SHA-256 일치를 검증했다. 백업은 서버 안에서 제한된 권한으로 보관하고 원본 자료를 로컬이나 Git에 가져오지 않았다.
- 브라우저 검사 후 재대조에서도 DB 전체와 보호 파일이 백업 시점과 일치했다. 기존 백업을 삭제하거나 덮어쓰지 않았다. 환경변수·키·인증서는 이번 교체 대상이 아니며 변경하지 않았다. 이번 백업은 서버 전체 재구축용 이미지가 아니다.

정확한 서버 백업 경로, 파일 해시와 검사 결과는 Git에서 제외되는 `work/deployment-blockers-20261118/backup-and-hash.json`과 서버 백업 내부 manifest에 기록했다. 복원 검사는 별도 디렉터리에서 했으며 운영 DB에 복원하지 않았다.

## 2. 배포 대상 해시와 서버 전용 코드

- collector 후보 14개 경로, API 후보 4개 경로 등 **18개 대상**의 후보 SHA-256을 재계산했다. 후보 manifest의 해시와 모두 일치한다.
- 실제 AWS 파일도 모든 적용 전 기준 해시와 일치했다. collector 새 모듈 3개는 예상대로 운영에 없었다. 새 파일의 부재와 기존 파일의 불일치를 구분했다.
- collector 대상: `config/collector_sources.json`; `support_official_apis.py`, `support_source_registry.py`, `run_support_collection.py`; `support_runtime/`의 `at_export`, `boards`, `conditions`, `core_facts`, `discovery`, `enrichment`, `ingestion`, `rda`, `regional`, `api_core` 모듈이다.
- API 대상: `rag_search.py`, `rag_sync.py`, `rag_catalogue.py`, `support_source_registry.py`이다. collector와 API는 서로 다른 실제 설치 경로를 대조했다.
- 서버의 `ingestion.py`와 `run_support_collection.py` 전용 갱신 훅은 유지돼 있다. 앞서 준비한 비공개 후보는 이 훅을 보존한다. **일반 저장소 파일을 그대로 덮어쓰는 방식은 계속 금지**한다.
- 운영 DB·승인 기록·수집 상태·공개 피드·서버 상세 19건·비공개 근거·환경변수·인증서·Nginx는 교체 대상에서 제외한다. API의 격리와 메모리 제한도 유지한다.

## 4. 미승인 자료 차단

- 별도 시험 피드에 유효한 형식의 미승인 공고 1개를 넣었을 때 전체 목록과 사업명 검색에 나타나지 않았다. 시험 데이터는 AWS에 쓰지 않았다.
- 상세정보의 승인 상태를 대기 상태로 만든 별도 브라우저 시험에서 공개용 상세 조회가 차단됐다. 기존 미승인 39항목 계획은 적용하지 않았다.
- 세 화면 크기에서 확인된 개인 신청 제외 조건은 불일치로 표시하고, 근거가 부족한 공고는 추가 확인 상태를 유지했다. 조건 일부 일치를 신청 가능 확정으로 표시하지 않았다.
- 신규 자동 안내 보류 옵션과 승인·권한 검사 이후 적용 순서는 직전 관련 테스트 결과를 재사용한다. 향후 코드 배포 시 `national-upgrade.service.d.conf.example`의 설정을 함께 적용해야 하며 이번에는 운영에 적용하지 않았다. 기존 출처 정책으로 공개된 기본 안내와 개인별 자격 승인은 별개다.

## 5. 배포 및 롤백 판정

**배포 준비 완료 — 검토된 코드 후보와 신규 안내 제한 설정의 반영에 한정한다.** 신규 공고나 미승인 39항목의 승인·공개 허가가 아니다. Push와 AWS 코드 배포는 수행하지 않았다.

적용은 [기존 최소 배포·롤백 순서](NATIONAL_INTEGRATION_PREFLIGHT.md)를 따른다. 승인 후 적용 직전에도 대상 원본 해시와 백업 이후 승인·수집 상태 변경 여부를 대조한다. 달라졌다면 최신 상태를 다시 백업하고 후보를 재대조한다. 전체 저장소 덮어쓰기나 최초 설치 도구 재실행은 하지 않는다.

실패 시 이번에 교체한 코드와 추가한 서비스 설정만 백업에서 복구한다. 현재 DB·승인·취소 상태와 비공개 근거는 보존한다. 필요하면 현재 승인 상태로 공개 피드를 재생성하며 과거 피드나 운영 DB를 무조건 되돌리지 않는다. DB 전체 복원은 별도 사고 복구 판단이 필요한 절차다.

API와 60초 갱신·07:00 수집 타이머는 검사 전후 활성 상태를 유지했다. API 재시작 0회, 현재 메모리 약 16.9MiB, 피크 약 17.2MiB, 제한 128MiB이며 서버 available 메모리는 약 451MiB다. 기존 김제·무주 수집 부분 실패는 남아 있으나 이번 작업에서 발생한 장애나 운영 파일 충돌은 아니다. 접근 제한을 우회하거나 수집기를 변경하지 않았다.
