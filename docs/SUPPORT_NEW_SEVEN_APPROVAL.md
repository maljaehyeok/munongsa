## 이용 근거와 적용 범위

이전 검토에서 제목·기관·링크 정책만으로 모든 상세 항목을 일괄 보류했던 결론을 구체화했다. **원문 저작물 이용허락과 객관적 사실 자체를 자체 표현으로 정리하는 것은 별개**다.

- [대법원 판례, 국가법령정보센터](https://www.law.go.kr/LSW/precInfoP.do?precSeq=197742)는 창작적 표현과 그 내용인 사실 자체를 구분한다. [법제처 생활법령 안내](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=1&cciNo=1&cnpClsNo=1&csmSeq=695)도 이 구분을 설명한다. 이번 계획은 날짜·수치·대상·서류명·접수 부서·공식 부서 전화만 선택해 짧은 자체 문장/항목으로 정리했다. 원문의 전체 문장 배열·표·설명문을 복제하지 않는다.
- [저작권법 제7조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033063839)는 국가·지자체 고시·공고 등을 별도로 다룬다. 다만 RDA에 재게시됐다는 이유로 모든 안내문·첨부가 이 조항에 해당한다고 포괄 판단하지 않았다. 이번 사실 정리는 원문 전체의 무제한 이용 허가를 전제로 하지 않는다.
- [농촌진흥청 정책](https://www.rda.go.kr/datacprprot.do)은 기관의 권리 보유 여부와 공공누리 유형을 구분한다. [파주시 정책](https://www.paju.go.kr/www/page_guide/page_guide_cp.jsp), [시흥시 정책](https://www.siheung.go.kr/main/contents.do?mId=0310010000), [안산시 정책](https://www.ansan.go.kr/www/common/cntnts/selectContents.do?cntnts_id=C0001386)도 저작물의 이용 범위·표시를 확인하도록 한다. 안산 본문은 검색 결과로 정책 내용을 확인했으나 직접 열기는 시간 초과였다. 어느 정책도 게시물 7건의 본문·첨부를 포괄 허락한 증거로 사용하지 않았다.
- 개별 공공누리 표시를 실제로 확인하지 않은 게시물에 제1유형 등의 허락을 임의 부여하지 않는다. `rights.use_basis`는 **사실정보 자체 정리의 근거**이며 제3자 허락 기록이 아니다. 사진·첨부·긴 원문 인용·작성자 설명문은 제외한다. 개인 이름·개인 이메일도 제외한다. 담당기관의 공개 문의 전화만 포함한다.
- 자동수집/서비스 약관·접근 정책은 저작권과 별도다. 이번에는 이미 로컬에서 검증된 7건의 자료만 재사용했다. 신규 수집·추가 API 호출·장래 자동수집 허용 범위 확대는 하지 않았다. 로봇 허용을 재배포 허가로 간주하지 않는다. 앞으로 수집을 확대할 때는 당시 접근 정책·서비스 약관·데이터베이스 이용 조건을 별도로 확인해야 한다.

이는 제한한 사실 항목의 공개 준비 판단이다. 향후 창작적인 설명문·이미지·첨부를 추가한다면 이 판단을 재사용할 수 없으며 해당 권한부터 확인해야 한다.

## 코드상 승인과 화면 연결

- 새 계획은 `reviewed_facts_v1` 표시 범위와 공개 항목 목록을 가진다. 기존 승인 도구는 사용자가 정확한 계획 해시를 승인한 경우에만 각 항목의 승인자·참조·시각을 기록한다. 로컬 미리보기는 항목 상태가 `preview`이며 운영 도메인에서는 차단된다.
- 기본 안내 공고도 공개 허용·본문 기준 일치·별도 상세 승인·항목 승인·이용 범위를 모두 통과한 항목만 화면에 표시한다. 공고의 기본 안내 상태나 자격 비교 결과를 변경하지 않는다. 승인 범위 밖이거나 항목 승인이 없으면 표시하지 않는다.
- 기존 11건의 이전 승인 방식은 유지한다. 새 범위 자료는 화면 표시 전용이다. `rag_search`와 `rag_sync`는 이를 상담 근거로 승격하지 않고 명시적으로 거부한다. GPT 상담의 기존 공식 사실 검증 경로는 유지한다.
- 공개 계획의 `evidence`에는 출처 URL·위치·확인일만 남겼고 원문 발췌 문장은 제거했다. 발췌가 있는 이전 검토 자료는 비공개 `work/`에 보존한다. 최종 계획·요약·미리보기 파일도 사용자 승인 전에는 Git에서 제외한다.

## 승인 후 적용 순서

로컬 검증: 관련 Python 21개, JavaScript 항목 승인/표시 20개와 링크 처리 11개를 통과했다. 최종 계획 7건의 스키마·허용 항목·발췌 제거·개인 이메일 제외·기존 11건 비중복과 보존도 확인했다. 기존 원문 조사와 PC·모바일 화면 전수검사는 반복하지 않았다. CSS·날짜 분류·자격 비교 알고리즘은 변경하지 않았다.

1. 사용자가 위 계획과 해시를 승인한 기록을 보관한다. 아직 명령을 실행할 권한을 받지 않았다.
2. 운영 서버의 실제 상세 JSON·공개 공고 상태·`basis`·최종 해시를 읽기 전용으로 대조하고 백업한다. 로컬 11건이나 빈 공개 피드로 서버 데이터를 덮어쓰지 않는다. 승인 계획과 운영 기준이 다르면 자동 재연결하지 말고 수정 계획의 해시를 다시 승인받는다.
3. 신규 7건만 기존 추가 전용 도구로 병합한다. 기존 4건을 포함한 11건은 교체하지 않는다. 보존 해시는 실제 병합 대상 파일에서 계산한다.
4. 같은 승인 결과의 웹 코드·상세 JSON을 임시 환경에서 확인하고 배포 해시를 갱신한 뒤 필요한 웹 파일만 적용한다. 기존 목록·승인 DB·07:00 수집·60초 갱신·TLS·보안 격리는 유지한다.
5. 실패하면 백업한 웹 코드·상세 JSON만 복원한다. 운영 DB·승인 이력을 초기화하거나 복원 대상으로 덮어쓰지 않는다. 새 설명 자료를 GPT 근거로 연결하는 별도 작업은 이번 범위에 포함하지 않는다.

이번 작업은 승인 준비·로컬 테스트·로컬 커밋까지만 수행한다. AWS 배포·GitHub Push·실제 승인·외부 LLM 호출은 하지 않는다.
