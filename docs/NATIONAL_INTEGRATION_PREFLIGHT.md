## 통합 수정 및 확인

- 오프라인 통합 도구는 기존 공식 ID 중복 제거와 자격 스키마를 재사용한다. 같은 ID의 사실 충돌은 보류하며 입력 자료를 변경하거나 승인하지 않는다.
- collector 배포 허용목록에 누락된 `core_facts.py`, `api_core.py`, `regional.py`를 추가했다.
- 신규 자동 안내를 제한하는 선택 옵션 `MUNONGSA_GUIDANCE_EXISTING_ONLY=1`을 추가했다. 기존 권한·승인 검사 이후 기존 안내 ID만 유지하며, 취소된 공고를 과거 피드로 되살리지 않는다. 정식 승인 경로는 유지한다. 기본값과 운영 설정은 변경하지 않았다.
- 두 API는 기존 운영 환경에 키가 등록돼 있고, 최근 운영 기록에서 각각 2회 요청·100건 응답·HTTP 200 인증 성공을 확인했다. 이번 작업에서 새 API 인증 호출이나 키 복사는 하지 않았다.
- 지역별 API 조회·출처 품질 선정 및 A/B/C/D 검토는 로컬 검토 경로다. 별도 자동수집 작업이나 운영 추천 경로를 새로 활성화한 것은 아니다. 기존 07:00 수집과 60초 근거 갱신을 보존한다.
- 최근 수집은 김제·무주 접근 차단으로 부분 실패했다. 접근 제한을 우회하거나 전체 수집을 반복하지 않았다.

## 배포 충돌 및 보호 대상

운영 collector의 `ingestion.py`, `run_support_collection.py`에는 서버 전용 승인 근거 갱신 훅이 있다. 저장소 파일을 그대로 덮어쓰면 훅이 사라진다. 비공개 작업 공간에 새 코드와 운영 훅을 결합한 후보 및 적용 전후 해시 목록을 준비했다. API 후보는 차이가 있는 4개 파일만 분리했다. 비공개 후보와 운영 코드 사본은 Git에 포함하지 않는다.

반드시 보존할 대상은 운영 DB·검토/승인 이력·권한 명세·공개 피드·서버 상세정보 19건·비공개 근거/해시·환경 설정·인증서·서비스/타이머·Docker 마운트다. 로컬 기본 데이터나 빈 피드로 교체하지 않는다. 미승인 39항목 계획은 적용하지 않았고 기존 해시를 보존한다.

## 향후 승인된 배포 순서

1. 배포 직전 현재 DB의 SQLite 일관 백업, 코드·서비스 drop-in·공개자료·비공개 근거와 해시 목록을 확보한다. 최근 백업은 무결성 검사에 통과했지만 DB 138건으로 현재 140건보다 오래됐다.
2. 후보의 기준 해시와 실제 운영 파일을 대조한다. 다르면 중단한다. 07:00 수집과 겹치거나 수집 잠금이 사용 중이면 적용하지 않는다.
3. 검토한 허용목록만 적용하며 서버 전용 훅을 보존한다. 신규 안내 제한은 제공한 service drop-in으로 추가한다. 기존 환경변수·계정·타이머·네트워크 격리·128MiB 제한을 교체하지 않는다.
4. 기존 운영 방식으로 필요한 코드만 갱신한다. 전체 Git 덮어쓰기, 최초 설치 도구 재실행, Docker 재구축은 사용하지 않는다. 운영 데이터와 승인 상태는 유지한다.
5. 기존 공개 ID·승인 이력·근거 검증·HTTPS와 PC/모바일 사용자 흐름을 확인한 뒤 반영을 확정한다. 실제 승인 없이 후보 공고를 공개하지 않는다.

롤백은 직전 백업의 변경 코드와 추가 drop-in만 복구한다. 코드 오류 해결을 위해 운영 DB를 과거로 되돌리지 않는다. 공개 피드는 현재 승인·취소 상태로 재생성하며 오래된 피드를 무조건 복원하지 않는다. 실제 복구 실행은 이번에 수행하지 않았다.
