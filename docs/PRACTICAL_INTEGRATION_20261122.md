# 사용자 실용성 중심 통합 개선

## 실제 변경

- 영농 프로필을 상담·지원사업·농업금융에서 공유한다. 거주지와 영농지를 구분하고 명시된 시·도와 시·군·구를 함께 전달한다. 제주와 제주시 같은 중복 이름은 저장된 행정단위로 복원한다.
- 상담의 실제 조건만 선택 화면에 반영하며 가정은 실제 프로필을 바꾸지 않는다. 새 대화는 대화와 목록 참조만 비운다. 영농 조건 전체는 탐색 화면에서 초기화한다.
- 금융 질문은 기존 공식 금융자료와 비교 엔진을 재사용한다. 보조금과 상환할 자금을 구분하며, 같은 조건으로 금융·지원사업 메뉴를 이동한다. 대출 승인·중복 수혜·자부담 충당을 보장하지 않는다.
- 필요 자금은 원 단위로 저장한다. 단위 없는 입력은 기존 만원 단위이며 `3,000만원`, `3000만원`, `30,000,000원`은 3천만 원이다. 음수·잘못된 쉼표·범위 초과를 거부한다. 보유 자금·사업비·희망 대출금은 각각 기억하고 필요 자금에 자동 대입하지 않는다.
- 일반 질문에 공고를 억지로 추천하지 않는다. 간단한 대화는 규칙으로, 나머지 일상 대화는 기존 GPT 호출의 짧은 응답으로 처리한다. 공식·농업·금융·의료·법률·최신 정보와 숫자·URL은 생성 응답 경로에서 차단한다. 기존 비용 한도·격리·실패 시 기본 안내를 유지한다.
- 일상 맥락은 식사·휴식·농담의 제한된 주제 코드만 보관한다. 전체 대화문을 모델에 재전송하거나 서버 사용자 프로필을 만들지 않는다. 같은 브라우저 탭의 상태이며 계정 동기화가 아니다.

## 검증 범위

PC 1440px·모바일 390px·320px에서 실제 입력·금액 환산·금융 후보·상세 이동·프로필 공유를 확인한다. 미등록 예비 청년, 시설자금 필요 농업인, 등록 노지 농업인, 제주 사용자, 조건 부족, 농업법인, 농식품기업 사례를 사용한다. 가상 사례이며 실제 농업인 평가로 표현하지 않는다.

배포 후보의 브라우저 검사는 HTTPS 사이트에서 변경 코드만 격리 교체하고 상담은 로컬 검증 자료로 대체한다. 실제 운영 검사는 배포 후 따로 구분한다.

## 보존과 한계

시작 기준 공개 126건·DB 234건·검토 이력 314건·상세 19건을 보존한다. 이번 변경은 신규 승인이나 지역 자격 확대가 아니다. 지역 근거 6건·일부 조건 비교 26건이라는 기존 데이터 부족은 남는다. 미승인 상세 39항목과 조건 후보를 적용하지 않는다.

일부 조건 일치는 전체 신청 가능 확정이 아니다. 연령 기준일·대상별 예외·실제 접수 여부는 공식 근거가 없으면 추가 확인이다. 일반 대화는 무제한 지식 답변이 아니다. 금융 가정 질문은 현재 실제 입력 기준 후보와 구분해 표시한다.

## 안전 배포

SQLite 공식 백업과 별도 복원 검증 후 운영 원본 해시를 대조한다. 서버의 미리보기 차단·금액 입력 상태 표시·NLU 작업자별 기존 비교 코드를 보존한다. API와 격리된 질문 해석 작업자의 주소 검증·응답 계약을 함께 적용한다. 운영 DB·피드·권한·승인 이력·자동수집·금융 원자료·재배기술은 교체하지 않는다. 오류 시 코드만 복구한다.

후보·원본·해시·복원 증명·화면·운영 결과는 비공개 `work/practical-integration-20261122/`에 기록한다. 키와 운영 DB는 Git에 포함하지 않는다.
