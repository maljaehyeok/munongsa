# 무농사 3.0 — 최종발표 일정·개발 로드맵

기준일: 2026-11-14. 사용자가 전달한 최신 일정·개발 지침을 반영한 현행 기준이다. 기존 문서의 12월 7일 일정과 충돌하는 계획은 이 문서로 대체한다. 과거 작업 기록은 당시의 사실로 보존한다.

## 1. 일정과 역할

- 기말발표: **2026년 11월 30일(월) 18:00**, 8분 발표 + 5분 질의응답.
- 멘토링: 총 3회 완료, 공식 인정 예정(사용자 제공 현황).
- 멘토링·발표자료 사업단 제출: **12월 1일(화) 09:00 이전**.
- 수업 최종 결과물 제출: **12월 14일까지**.
- PPT와 약 1분 소개영상은 다른 팀원이 담당한다. 최종보고서는 각자 담당 부분·개인 회고·AI 활용 기록을 준비한다.
- Codex는 PPT·영상·보고서를 임의 제작하지 않는다. 개발 및 검증 기록을 보존하고, 요청받은 작업만 수행한 뒤 다음 지시를 기다린다.

## 2. 서비스 목표와 개발 판단

무농사는 농업인이 자신의 조건에 맞는 공식 지원사업을 찾고, 신청 자격과 지원 내용을 이해하며, 실제 신청 준비까지 이어가도록 돕는 전문 웹서비스다. 정보 탐색에 어려움을 겪는 농업인을 중심으로 예비·청년·영농 초기 농업인을 고려한다. 범용 대화형 AI 개발을 목표로 삼지 않는다.

공식 정보원의 지속 수집, 원문·첨부 검증, 세밀한 자격 비교, 추천 이유·불일치·미확인 설명, 정확한 기간·금액·접수처, 신청 준비 지원, 금융·재배기술 연결을 우선한다. 수집량이나 AI 기능 수만으로 가치를 주장하지 않는다.

교수님 중간발표 피드백과 11월 13일 김제 스마트팜 혁신밸리 멘토링의 목적 명확화 의견을 반영해 다음을 검토한다.

1. 누구를 위한 기능이며 농업인의 어떤 불편을 해결하는가?
2. 기존 검색·일반 GPT와 비교해 어떤 추가 가치가 있는가?
3. 설명 없이 사용할 수 있으며 정확성·실용성을 객관적으로 검증할 수 있는가?

답이 불명확하면 우선순위나 범위를 줄인다. 실제 농업인 사용성 평가와 일반 GPT 대비 우수성은 미검증이며 성과 수치를 만들지 않는다.

## 3. 평가 기준

다음은 **사용자가 제공한 2026년 11월 13일 WE-Meet 안내자료 기준**이다. 이번 작업에서 원 안내자료를 별도로 재검증하지 않았으며 수업 기말발표 배점과 동일하다고 단정하지 않는다. 이전 2025년 참고 기준을 현행 확정 기준으로 사용하지 않는다.

| 평가 | 항목과 배점 |
| --- | --- |
| 예선 | 분야 적합성 20, 문제해결 논리성 20, 접근의 다양성 20, 실현 가능성 10, 교육효과 30 |
| 본선 | 분야 적합성·연계성 20, 문제해결 논리성 20, 실무 적용력 30, 결과물 완성도 20, 전달력 및 태도 10 |

농업 문제 정의, 적절한 기술 결합, 피드백 반영, 현장 활용성, 안정적인 시연, 팀원의 기술·문제해결 역량을 근거로 설명한다.

## 6. 사실 검증·운영 보호 원칙

- GPT는 질문 이해·조건 추출·맥락 해석·일반 안내와 질문 재확인을 담당한다. 실제 구현된 의도 처리와 자유 답변 생성을 혼동하지 않는다.
- 사업 존재, 자격 비교, 금액·한도, 모집기간, 서류·신청 방법은 승인된 공식 근거와 기존 검증 엔진이 담당한다. 불명확하면 추가 확인 필요로 보류한다. 금융·재배기술에도 같은 원칙을 적용한다.
- 기재 모집기간과 실제 접수 가능, 일부 조건 일치와 전체 자격 확정, 승인 요약과 원문 전체 검증을 구분한다.
- 공식 DB·승인 이력·공개 피드·백업, GPT 호출 제한, 거주지/영농지·실제/가정 분리, 금융·재배기술, 07:00 수집·60초 갱신·HTTPS를 보존한다. 미승인 자료는 공개 상담에 사용하지 않는다.
- 키·개인정보·비공개 원문·운영 DB는 저장소에 추가하지 않는다. 서버 증설·불필요한 의존성·대규모 재구축은 하지 않는다.
- GPT 대체 응답 사례가 재발하면 비밀정보 없이 원인을 진단하되 서비스가 계속 작동하도록 한다. 원인 미확인을 해결 완료로 기록하지 않는다.

## 7. 개발·AI 활용 기록과 이번 작업 범위

각 작업은 문제 → 기존 한계 → 기술·개선 방법 → 실제 검증 → 전후 차이 → 사용자 가치 → 남은 한계를 간결하게 남긴다. 사용 도구·주요 프롬프트·코드 검증 방법·사람의 판단과 검토를 추적할 수 있도록 기록한다. 보고서·WE-Meet 근거로 쓸 때 실제 확인과 추정을 구분한다.

이번에는 일정·지침·현황·로드맵 문서만 갱신했다. 신규 기능, UI 재수정, DB 변경, 공고 승인, 금융·재배기술 개발, 커밋·Push·AWS 배포는 수행하지 않는다. 기존 서비스의 재검사도 반복하지 않는다. 다음 개발은 사용자 지시 후 시작한다.
