# 1. 무농사의 정체성과 개발 목적

## 1.1 서비스 정의

무농사는 농업인의 상황을 자연어 대화와 간편한 선택형 입력으로 파악하고, 공식 농업 지원사업의 신청 조건을 비교하여 관련 지원사업과 다음 행동을 안내하는 **농업 지원사업 전문 AI 상담 서비스**다.

무농사는 다음 세 가지에 집중한다.

1. 농업 지원사업 정보를 지속적으로 수집하고 검증한다.
2. 농업인의 실제 조건과 공식 신청 자격을 세밀하게 비교한다.
3. 농업인이 자신에게 관련된 지원사업을 이해하고 신청 준비까지 이어가도록 돕는다.

**챗봇 자체가 목적이 아니다. 농업인의 지원사업 탐색 문제를 해결하는 것이 목적이다.**

## 1.2 주요 사용자

주요 사용자는 지원사업 탐색과 신청 조건 이해에 어려움을 겪는 농업인이다.

- 농업을 처음 시작하려는 예비 농업인
- 청년·초보 농업인
- 독립영농을 준비하는 사람
- 기존 농업인 중 새로운 지원사업을 찾는 사람
- 지역·작물·영농 형태에 맞는 사업을 찾는 사람

청년 농업인은 중요한 사용자층이지만, 모든 서비스를 청년에게만 제한하지 않는다.

## 1.3 해결하려는 문제

- 농업 지원사업 공고가 여러 기관에 분산되어 있다.
- 공고마다 신청 대상과 자격조건이 다르다.
- 거주지, 영농지, 연령, 경영체 등록, 영농 경력 등 조건을 비교하기 어렵다.
- 지원금, 신청기간, 신청 방법, 제출 서류 등을 찾는 데 시간이 걸린다.
- 자신에게 실제로 관련 있는 사업인지 판단하기 어렵다.
- 오래되거나 불완전한 정보 때문에 신청 가능성을 오해할 수 있다.

무농사는 이러한 문제를 해결하기 위한 서비스여야 한다.

# 4. 일반 ChatGPT와의 차별화 전략

## 4.1 현실적인 경쟁 환경

일반 ChatGPT도 다음 기능을 수행할 수 있다.

- 자연어 질문 이해
- 인터넷 검색
- 공식 공고 검색
- 지원사업 요약
- 조건에 대한 추가 질문
- 공식 출처 안내

따라서 단순히 GPT를 연결하거나 지원사업을 검색·요약한다는 사실은 강력한 차별점이 아니다.

**무농사가 일반 GPT보다 무조건 우수하다고 가정하지 않는다.**

## 4.2 무농사가 집중해야 할 차별점

### A. 공식 지원사업 데이터의 전문성

중앙정부, 지자체, 농업 관련 공공기관의 공식 지원사업 소스를 지속적으로 확보한다.

공고가 새로 게시되거나 변경되면 자동으로 발견하고 검토할 수 있어야 한다.

개별 공고를 수동으로 추가하는 방식보다 **공식 게시판·API·RSS 등 소스 자체를 자동수집 시스템에 연결하는 방식**을 우선한다.

### B. 세밀한 신청 자격 비교

공고에 명시된 자격조건을 구조화하고 사용자 조건과 비교한다.

주요 항목:
- 거주지
- 실제 영농지 또는 영농 예정지
- 연령 및 연령 기준일
- 농업경영체 등록 여부
- 독립경영 여부
- 영농 경력
- 재배 작물
- 경작 면적
- 개인·단체·법인 구분
- 지원 목적
- 기타 공고별 필수 요건

모든 공고에 동일한 조건을 강제로 적용하지 않는다.

### C. 근거에 기반한 판단

각 자격조건은 가능한 경우 공식 공고의 근거 문장과 연결한다.

다음 상태를 명확히 구분한다.

- 확인된 조건에 부합
- 확인된 조건과 불일치
- 사용자 정보 부족
- 공식 자료의 정보 부족
- 모집 종료
- 모집 상태 확인 필요

'정보 없음'을 '제한 없음'으로 해석하지 않는다.

'관련 가능성 있음'을 '신청 가능 확정'으로 표현하지 않는다.

### D. 실제 신청 행동 지원

가능한 경우 공식 근거를 바탕으로 다음 정보를 안내한다.

- 지원사업명
- 사업 목적
- 지원 대상
- 지원 내용 및 금액
- 신청기간
- 신청 방법
- 신청 장소 또는 공식 접수처
- 제출 서류
- 문의처
- 공식 원문 링크
- 추가 확인이 필요한 자격조건

확인할 수 없는 정보는 임의로 작성하지 않는다.

## 4.3 최종 경쟁력

무농사는 '대화를 잘하는 AI'보다 **'공식 농업 지원사업을 정확하게 비교하고 실제 신청 준비를 돕는 전문 서비스'**가 되어야 한다.

# 5. 챗봇과 기존 조건 검색의 통합

## 5.1 최종 UX 방향

서비스의 중심은 AI 챗봇이다.

다만 사용자가 모든 정보를 직접 타이핑하도록 강요하지 않는다.

**자연어 입력 + 선택형 조건 입력 + 공식 공고 추천**을 하나의 상담 흐름으로 통합한다.

### 권장 흐름

1. 사용자가 자유롭게 질문하거나 조건 선택으로 시작한다.
2. GPT가 이미 제공한 정보를 구조화한다.
3. 누락된 핵심 조건만 선택형 카드·버튼으로 묻는다.
4. 사용자가 여러 조건을 한 번에 선택할 수 있도록 한다.
5. 현재 확보된 조건만으로도 우선 관련 사업을 검색한다.
6. 특정 공고의 판정에 필요한 조건만 추가로 확인한다.
7. 추천 결과에서 이유와 공식 근거를 보여준다.
8. 사용자가 이어서 질문하거나 조건을 변경할 수 있도록 한다.

## 5.2 UX 필수 원칙

- 사용자가 이미 알려준 조건은 다시 묻지 않는다.
- 조건을 하나씩 계속 질문해 대화가 길어지지 않게 한다.
- 여러 조건을 한 카드에서 선택할 수 있도록 한다.
- '잘 모르겠어요', '건너뛰기'를 제공한다.
- 조건을 모두 입력하지 않아도 검색할 수 있다.
- 입력한 조건을 언제든 확인하고 수정할 수 있다.
- 사용자의 실제 조건과 가정 질문을 구분한다.
- 거주지와 영농지의 의미를 구분한다.
- 모바일에서도 조건 선택과 결과 확인이 편리해야 한다.
- 사용자가 원한다면 자유로운 자연어 질문도 계속할 수 있어야 한다.

## 5.3 기존 조건 검색과의 관계

챗봇과 기존 독립 조건 검색은 같은 추천 엔진과 자격 비교 기준을 사용한다.

두 기능을 위한 별도 판정 로직을 중복 개발하지 않는다.

이미 구현된 챗봇 내 조건 선택 기능을 우선 활용한다.

기존 독립 조건 검색은 사용자 검증 전까지 유지하고, 통합형 상담의 편의성이 확인된 후 삭제·축소 여부를 결정한다.

**현재 통합 기능은 구현 완료 보고 상태이므로, 추가 UX 문제가 확인되지 않는 한 전면 재개발하지 않는다.**

- 추천 결과의 일관성 유지

GPT가 공식 자료에 없는 자격조건이나 지원금액을 만들어내면 안 된다.

GPT의 해석 결과는 구조화된 데이터로 검증한 후 사용한다.

공식 공고 원문 전체를 불필요하게 외부 API로 전송하지 않는다.

개인정보 전송을 최소화하고, API 키는 서버 비밀 환경변수로 관리한다.

# 7. 농업인 관점에서 필요한 정보

아래 항목은 사용자 요구에 대한 현재 가설이다. 실제 농업인 검증을 통해 우선순위를 확인해야 한다.

## 사용자가 가장 먼저 알고 싶은 것

1. 나에게 관련된 지원사업이 있는가?
2. 지금 신청할 수 있는가?
3. 신청 대상에 해당하는가?
4. 어떤 지원을 얼마나 받을 수 있는가?
5. 신청하려면 무엇을 준비해야 하는가?
6. 언제까지 어디에서 신청해야 하는가?
7. 자격이 부족하다면 무엇을 확인하거나 준비해야 하는가?

## 사용자 경험 개선 원칙

### 정보의 우선순위

추천 결과에서 다음 순서를 우선 검토한다.

1. 사업명과 모집 상태
2. 사용자 조건과의 관련성
3. 추천·불일치·미확인 이유
4. 지원 내용
5. 신청기간 및 방법
6. 공식 출처와 상세 근거

처음부터 긴 공고 전문을 보여주지 않는다.

### 사용자 언어

'독립경영', '농업경영체', '영농 경력' 등 어려운 용어는 필요하면 간단히 설명한다.

사용자가 자신의 상태를 잘 모르더라도 상담을 계속할 수 있어야 한다.

### 검색 결과가 없는 경우

단순히 '결과 없음'만 표시하지 않는다.

다음 원인을 가능한 범위에서 구분한다.

- 현재 공개된 공고에 관련 사업이 없음
- 조건 불일치
- 모집 종료
- 정보 부족
- 아직 수집·검증되지 않은 사업이 있을 가능성

**무농사 DB에 없다는 이유만으로 실제 지원사업이 존재하지 않는다고 단정하지 않는다.**

# 8. 공식 지원사업 소스 확대 전략

## 8.1 핵심 목표

개별 공고를 일회성으로 수동 등록하는 것이 아니라 **공식 지원사업 소스를 지속적으로 자동수집할 수 있는 구조**를 확대한다.

## 8.2 우선 검토 대상

실제 공고 게시 구조와 접근 가능성을 확인한 후 우선순위를 결정한다.

- 농림축산식품부
- 농촌진흥청
- 농림수산식품교육문화정보원
- 한국농어촌공사
- 농업 관련 중앙 공공기관
- 전북특별자치도
- 전북 시·군 지자체 및 농업기술센터
- 이후 전국 지자체로 확장

특정 기관의 모든 게시물이 지원사업은 아니다.

농업인이 신청할 수 있는 사업을 우선 수집한다.

## 8.3 수집 확대 원칙

1. 기존 수집 소스와 실제 수집 성과를 파악한다.
2. 수집 실패, 비관련 게시물, 승인 대기 등 병목을 구분한다.
3. 공고 가치가 높고 안정적으로 수집 가능한 공식 소스를 우선 연결한다.
4. 공식 API·RSS가 있다면 우선 검토한다.
5. HTML 수집 시 이용 조건과 기술적 접근 제한을 준수한다.
6. PDF·HWP 첨부자료의 내용 확인 가능성을 검토한다.
7. 공식 원문 링크, 출처, 게시일, 모집기간, 변경 이력을 관리한다.
8. 자동수집과 자동공개를 혼동하지 않는다.
9. 검증되지 않은 공고는 공개하지 않는다.
10. 서버 자원과 운영 부담을 고려한다.

## 8.4 성과 지표

단순 DB 총건수만 보고하지 않는다.

- 연결된 공식 소스 수
- 정상 수집 소스 수
- 신규 수집 공고 수
- 검토 대기 공고 수
- 승인·공개 공고 수
- 실제 모집 중으로 확인된 공고 수
- 자격조건 비교가 가능한 공고 수
- 공식 원문 근거가 충분한 공고 수

수집량이 늘어도 검증 가능한 공개 공고가 늘지 않으면 원인을 분석한다.

### 지역
- 거주지
- 영농지
- 사업장 소재지
- 해당 지역 거주 또는 영농 기간

### 연령

- 공고의 조건이 불명확하면 임의로 해석하지 않는다.
- 추천 가능성과 신청 자격 확정을 구분한다.
- 접수기간 내에 있다고 실제 접수 가능 상태로 단정하지 않는다.
- 사업의 연도와 기준일을 정확하게 구분한다.

# 10. 일반 ChatGPT와의 객관적 비교 검증

최종발표에서 일반 ChatGPT보다 무농사가 우수하다고 주장하려면 객관적 근거가 필요하다.

## 비교 방식

동일한 농업인 상황과 질문을 일반 ChatGPT와 무농사에 각각 입력한다.

예시:
- 전주 거주, 김제 영농 예정, 30세, 벼 재배
- 농업경영체 미등록 예비 농업인
- 독립경영 여부가 불명확한 청년 농업인
- 특정 작물 지원사업을 찾는 기존 농업인
- 모집 종료 사업에 대해 질문하는 사용자

## 평가 항목

1. 관련 공식 공고 발견율
2. 자격조건 비교 정확도
3. 잘못된 신청 가능 판정 수
4. 근거 없는 정보 제공 여부
5. 모집 상태 판단 정확도
6. 사용자 탐색 소요 시간
7. 신청 방법과 공식 링크 확인 가능 여부
8. 사용자의 이해도와 만족도

공정한 평가를 위해 양쪽 서비스가 찾은 공고를 독립적인 공식 자료로 확인한다.

무농사 DB에 있는 공고만 정답으로 취급하지 않는다.

비교 결과가 불리하다면 그대로 보고하고 개선 과제로 반영한다.

# 13. 개발 시 주의사항

## 기존 시스템 보존
- 이미 구현된 기능을 불필요하게 재개발하지 않는다.
- GPT 연결을 유지한다.
- 챗봇 선택형 입력을 유지한다.
- 공식 근거 검색·자격 비교 엔진을 유지한다.
- DB·승인 이력·자동 갱신을 보존한다.
- 기존 AWS 서버 사양에서 운영한다.
- 명확한 필요성과 승인 없이 서버를 업그레이드하지 않는다.

## 정확성
- 공식 자료를 최우선으로 한다.
- 출처가 불확실한 내용을 확정적으로 제공하지 않는다.
- 지원금액·신청기간·자격조건을 추측하지 않는다.
- 검증되지 않은 공고를 자동 승인하지 않는다.
- 공고의 연도·기준일·모집 상태를 구분한다.
- AI의 해석 결과와 공식 사실을 구분한다.

## 사용자 경험
- 농업인이 이해하기 쉬운 용어를 사용한다.
- 불필요한 입력과 대화를 최소화한다.
- 모바일 사용성을 우선한다.
- 추천 결과에서 중요한 정보를 먼저 보여준다.
- 결과가 없거나 판단할 수 없을 때 이유를 설명한다.
- 화면을 복잡하게 만드는 기능은 추가하지 않는다.

## 개발 효율
- 한 번에 하나의 주요 개발 목표를 완료한다.
- 기존 기능을 활용할 수 있다면 재사용한다.
- 반복적인 검증 전용 작업을 최소화한다.
- 구현에 필요한 테스트만 수행한다.
- 기능 구현 후 GitHub와 AWS에 반영한다.
- 완료되지 않은 기능을 완료했다고 보고하지 않는다.
- 실제 운영 결과와 추정·계획을 구분한다.
- 중요한 기술적 제약이나 서비스 방향 변경은 임의로 결정하지 말고 보고한다.

# 15. Codex에게 요청하는 다음 행동

이 문서를 앞으로의 프로젝트 개발 기준으로 삼는다.

먼저 현재 코드와 운영 구조를 기준으로 위 내용 중 실제 구현 상태와 차이가 있는 부분만 파악한다.

그다음 **공식 지원사업 소스 확대**를 다음 주요 개발 작업으로 진행한다.

이번 작업에서는 다음 사항에 집중한다.

1. 기존 수집 소스별 수집·검토·공개 현황과 병목 파악
2. 농업 지원사업 가치가 높은 공식 소스 우선 선정
3. 기존 수집 시스템과 호환되는 신규 소스의 실제 연결
4. 수집된 공고의 공식 출처·자격조건 검증
5. 기존 승인 절차와 챗봇 추천 기능 보존
6. AWS 배포 및 GitHub 반영

**계획서 작성만으로 작업을 끝내지 않는다.** 현재 환경에서 구현 가능한 범위는 실제로 구현하고, 접근 제한이나 기술적 장애가 있는 부분만 구체적으로 보고한다.

단, 대규모 구조 변경이나 검증되지 않은 공고의 자동공개는 수행하지 않는다.

## 최종 개발 원칙

무농사의 경쟁력은 GPT를 연결했다는 사실이 아니다.

**공식 농업 지원사업을 지속적으로 확보하고, 농업인의 조건을 세밀하게 비교하여, 신뢰할 수 있는 근거와 실제 신청에 필요한 정보를 제공하는 능력**이 핵심이다.

최종발표까지 이 목적에 집중한다.
