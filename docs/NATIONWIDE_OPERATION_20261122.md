## 재사용 가능한 코드 개선

- 기업마당: 기존 최신 공고 조회를 유지하면서 매일 공식 지역 태그 3개를 순환한다. 6일간 공급자의 모든 지역 태그를 다루며 전남/광주를 신청 자격에서 임의 합치지 않는다. 공공데이터 API는 첫 페이지를 매일 유지하고 두 번째 조회를 2~30페이지 사이에서 순환하여 앞쪽 100건에 고정되는 문제를 해소한다. 인증 오류·한도 초과를 재시도하지 않고, 부분 조회로 기존 공고의 부재를 판정하지 않는다. 공개 재검증의 2초/30페이지/150초 제한은 그대로다.
- RDA: 최대 4페이지와 모집 예정 경로를 기존 파서에 연결했다. 실제 이번 조회에서 모집 예정 신규 공고를 확보했다고 주장하지 않는다.
- API 개요: 명시된 대상/지원 문장 쌍을 기업·기관 대상에서도 사실정보로 보존한다. 농업인 자격으로 자동 전환하지 않는다.
- 중복: 기업마당의 공식 PBLN 번호가 같은 경우 호스트·상세 템플릿 변경에도 같은 식별자로 연결한다. 다른 ID나 회차를 제목 유사성으로 병합하지 않는다.
- 추천: 공식 조건에 명시된 시·도와 기초지자체를 비교할 때 기존 UI의 짧은 도시 목록에 없는 시·군도 상위 시·도 불일치를 확인할 수 있게 했다. 같은 시·도의 상세 지역 미입력은 계속 확인 필요다. 17개 시·도의 정식 명칭을 화면과 서버에서 일관되게 비교한다. 같은 자격 판정 안에서 모집 예정·상시 공고를 기간 미확인보다 앞에 둔다. 자격 불일치를 기간 순위로 뒤집지 않는다.

## 배포 차이와 안전장치

운영 호스트의 personalization 소스는 `ea5ed7b`와 정확히 같은 구버전이었다. 실제 서비스 컨테이너의 정상 A/B/C/D 구현을 보존하면서 호스트 소스도 현행 구현과 연결하여 향후 빌드 회귀를 막는다. 운영 웹에 누락돼 있던 기존 Git의 로컬 검토 자료 차단문도 동기화한다. 수집 모듈에 덧붙은 서버 전용 승인 근거 훅은 그대로 보존한다.
