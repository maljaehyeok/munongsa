# 지원사업 상세정보 11건 공개 준비 검토 (2026-11-17)

이 문서의 “승인 대기”는 새 초안에 관한 기록이다. 기존 승인 상세자료까지 0건이라는 뜻은 아니다. 이후 확인한 코드상 차단 조건과 승인 방법은 [승인 결정표](SUPPORT_APPROVAL_ACTIONS.md)를 우선 적용한다.

## 판정과 공개 경계

**A 공개 준비 완료 0건 / B 일부 정보 공개 후보 11건 / C 공고 자체 보류 0건.**

B는 기존 `support_link_policy.py`가 허용하는 **공고 제목·기관·공식 링크** 범위의 판단이다. 상세 본문·신청조건·금액의 공개 승인 완료를 뜻하지 않는다. 이번에 새로 승인하거나 공개 데이터에 추가한 항목은 없다. 상세정보 11건은 모두 로컬 승인 대기 상태다.

공식 URL 11건을 2026년 11월 17일 20:04경 한국시간에 직접 다시 조회했다. 모두 HTTP 200, 예상 공식 URL 유지, 상세 본문 존재, 직전 확인 본문과 일치를 확인했다. 제목은 RDA 상세 제목 요소 또는 aT의 사업명 표에서 각각 대조했다. 이 결과는 현재 접수 성공이나 전체 신청 자격 검증이 아니다.

농촌진흥청 [저작권 정책](https://www.rda.go.kr/datacprprot.do)은 기관이 전체 권리를 보유한 자료와 그 밖의 자료를 구분한다. 지자체 재게시 자료의 전체 권리가 농촌진흥청에 있다고 추정하지 않았다. aT 정책 페이지는 이번 직접 요청에서 오류가 발생했고, 수출지원 포털 본문의 재게시 범위까지 확인하지 못했다. 양쪽 모두 기존 최소 사실정보·링크 정책만 적용하고 새 본문·첨부 공개는 보류한다.

## 코드 수정과 로컬 연결

- 추출기의 선택지 정규식 묶음 오류를 수정했다. 신청 대상의 반복 문구와 숫자 목차 때문에 값이 잘리거나 다음 항목 번호가 붙던 문제를 고쳤다. 괄호 안 동지역 접수처 예외도 보존한다. 필수서류와 다음 번호의 동의 절차를 분리한다.
- 검토용 표시가 있는 공고를 정상 피드에 섞어도 일반 검색과 상담 검색이 거부하도록 보완했다. 기존 승인 데이터나 자격 판정 방식은 바꾸지 않았다.
- 로컬 미리보기는 `?support-details-preview=1`과 localhost 조건을 모두 충족해야 하며 `work/core-final-validation/preview-details.json`, `preview-feed.json`을 읽는다. 기본 접속에서는 이 파일들을 요청하지 않는다.
- 공식 원문·승인 대기 계획·검토 피드·확인 결과·화면 이미지는 Git에서 제외되는 `work/core-final-validation/`에만 저장한다. 원문이나 첨부를 공개 저장소에 넣지 않는다.

## 배포 전 필수 순서 — 이번에는 실행하지 않음

1. 운영 상세 JSON·공개 피드·현재 코드·배포 해시를 읽기 전용으로 대조하고 서버 내부 비공개 백업을 확보한다. 신규 저장소의 기본 JSON으로 운영 자료를 덮어쓰지 않는다.
2. 상세 내용의 출처별 표시 범위와 최종 허용 필드를 확정하고, 그 필드만 포함한 계획의 정확한 해시를 관리자에게 승인받는다. 이번 검토 결과를 승인 기록으로 대체하지 않는다.
3. 기존 상세자료와 겹치는 4건, 신규 후보 7건을 분리한다. 기존 도구는 승인 자료의 **추가만 허용**하므로 11건 계획을 그대로 승인·교체할 수 없다. 기존 4건은 보존하고, 교체가 필요하면 별도의 명시적인 수정 승인 절차부터 정한다. 신규 7건도 권한·내용 승인 전에는 추가하지 않는다.
4. 승인된 변경만 임시 데이터에서 생성·검사한 뒤 운영 상세자료와 원자적으로 교체한다. 웹 코드는 `index.html`, `assets/support-public.js`, `assets/support-details.js` 및 이전 UI 변경 파일을 대조한다. API 변경은 `scripts/rag_catalogue.py`의 검토 자료 차단이며 현재 API 릴리스에 실제 필요한지 먼저 확인한다.
5. 설명용 상세 JSON은 자격 비교나 GPT 승인 근거의 대체 자료가 아니다. 운영 승인 DB·근거 해시·갱신 절차를 별도로 확인하며 이 변경만으로 새 조건을 판정 엔진에 넣지 않는다.
6. 문제 발생 시 변경한 웹/API 코드와 상세 JSON만 기존 백업으로 복원한다. DB·승인 이력·수집·인증서·systemd 보안 설정은 복구 대상으로 덮어쓰지 않는다.
