## 프로젝트 소개

농업을 시작하려는 사람은 지원사업 공고, 정책금융, 작물별 재배기술을 서로 다른 기관에서 찾아야 합니다. 자료를 찾더라도 *내 상황에 맞는지*, *어떤 조건을 확인해야 하는지*, *어디에서 신청하거나 자세히 알아볼 수 있는지* 판단하기는 쉽지 않습니다.

무농사는 그 과정을 하나의 흐름으로 연결합니다.

**영농 상황 입력 → 관련 정보 탐색 → 확인 가능한 공식 조건 비교 → 신청 준비·공식 원문 연결**

> **핵심 원칙:** 관련 자료를 찾았다는 이유만으로 신청 가능하다고 판단하지 않습니다. 공식 근거로 확인한 조건과 미확인 항목을 명확히 나눠 보여줍니다.

## 주요 기능

### 01. 농업 지원사업

- **공고 탐색:** 지역·작물·관심 분야·모집 상태 등을 기준으로 관련 자료 검색
- **일부 자격조건 비교:** 사용자 입력과 검증·승인된 공식 조건을 비교하여 일치·불일치·추가 확인 필요 구분
- **신청 준비:** 공식적으로 확인된 신청 경로와 준비정보를 안내하고 공고 원문으로 연결
- **AI 상담 연계:** 공고 탐색 후 같은 공고에 관한 후속 질문 지원

**주의:** 조건 일부가 맞더라도 전체 신청 자격을 충족한다는 의미는 아닙니다. 모집 상태와 최종 자격은 공식 공고에서 다시 확인해야 합니다.

### 02. 농업금융

**공개된 16개 금융·지원 제도**를 자금 목적별로 탐색합니다.

- 창업·시설 투자·농지·주택 관련 자금 검색
- 융자·보증·농지 지원·농지연금처럼 성격이 다른 제도 구분
- 제도별 **근거가 확인된** 대상·용도·한도·금리·상환정보 안내
- 검색·상세정보·AI 상담에 같은 승인 자료 사용
- 기존 후계농 자금의 **명시된 가정에 따른 단순 이자 계산** 제공

미확인 금리나 실제 접수 여부를 임의로 확정하지 않습니다. 제도의 최대 한도는 개인별 대출 승인액과 다릅니다.

### 03. 재배기술

- **67종 작물·8개 분류**에서 작물명 및 별칭 검색
- 대표 작물 8종 우선 표시, 필요 시 전체 작물 탐색
- 작물·주제에 맞춘 공식 재배정보·병해충·농약·토양 자료 연결
- 선택 작물·주제 복원 및 실제 영농 프로필과 임시 자료 탐색 분리

농사로, 국가농작물병해충관리시스템, 농약안전정보시스템, 흙토람 등 공식 서비스로 연결합니다. 자료에 따라 외부 사이트에서 작물이나 재배조건을 추가로 입력해야 할 수 있습니다.

### 04. AI 농업 상담

- 자연어로 지원사업·금융·재배기술 탐색
- 지역·분야·조건을 대화 중 수정하고 후속 질문
- 이전 공고·금융제도를 가리키는 대화 맥락 유지
- 실제 영농정보와 임시 가정·검색 조건 구분
- 일반 농업 개념을 쉽게 설명하고 필요한 경우 공식 자료로 연결

상담은 **규칙 기반 처리와 필요한 경우의 OpenAI API 호출**을 함께 사용합니다. GPT 호출이 제한되거나 실패해도 가능한 범위에서 기본 안내로 이어가며, 모든 질문에 생성형 응답이 제공되는 것은 아닙니다.

## 이렇게 사용할 수 있어요

**예시: 전북에서 토마토 재배를 준비하는 예비 농업인**

1. **영농 상황 입력** — 지역과 현재 상황 등 필요한 조건 선택
2. **지원사업 탐색** — 관련 공고와 확인 가능한 일부 자격조건 비교
3. **농업금융 확인** — 농지·시설·창업 목적에 맞는 금융제도 살펴보기
4. **재배기술 탐색** — 토마토와 원하는 주제의 공식 자료 확인
5. **다음 행동 결정** — 신청 준비사항과 원문·담당 기관 안내 확인

특정 서비스에서 검색한 정보가 곧바로 다른 서비스의 **공식 자격 판정**으로 바뀌지는 않습니다.

## 개발에서 중점적으로 해결한 문제

캡스톤 과정에서는 기능을 추가하는 것뿐 아니라, **공식 근거의 신뢰성·사용자 입력의 정확성·실제 운영의 안정성**을 반복 개선했습니다.

| 개선 영역 | 해결한 문제와 적용한 방식 |
| --- | --- |
| **검색과 자격 비교** | 단순히 관련성이 높은 공고를 보여주는 것과 **공식 자격조건의 일부 일치 여부**를 분리했습니다. 지역·작물 검색 범위와 실제 영농정보도 별도로 관리합니다. |
| **대화 맥락** | 지원사업·금융제도 후속 질문에서 이전 대상을 참조하되, 주제가 바뀌면 오래된 검색 조건을 부적절하게 재사용하지 않도록 개선했습니다. |
| **금융정보 신뢰성** | 기존 4개 중심 목록을 **16개 공개 제도**로 확장했습니다. 미확인 금리·한도·접수 여부를 확정하지 않고, 제도별로 승인된 정보만 안내합니다. |
| **재배기술 탐색** | 67종 전체를 한 번에 보여주지 않고 **대표 8종 → 검색·분류 → 주제별 공식 자료** 순서로 정리했습니다. 선택한 작물과 주제는 새로고침 이후에도 복원할 수 있습니다. |
| **입력과 화면 일치** | 선택·적용·검색 지우기·작물 선택 해제·영농정보 초기화를 구분하여, 임시 탐색이 실제 영농 프로필을 덮어쓰지 않도록 했습니다. |
| **접근성·가독성** | 알약형 버튼, 명확한 선택 표시, 정보 상태별 안내 색상, 모바일 한글 줄바꿈과 키보드 조작을 개선했습니다. |
| **운영 보호** | 비공개 검토자료의 공개를 차단하고, 승인 버전 검증·자동수집·백업 및 별도 복원 검사를 적용했습니다. |

### AI 상담과 동시 접속 대응

- GPT 호출은 서비스 전체 공용으로 **하루 최대 120회·분당 최대 6회**로 제한하며, 토큰·비용 예약 상한을 둡니다.
- 개인 영농정보와 무관한 **일반 농업 개념 질문**은 제한적으로 캐시하여 불필요한 반복 호출을 줄입니다.
- GPT 응답이 실패하거나 한도에 도달하면 가능한 범위에서 기존의 규칙 기반 기본 설명을 활용합니다.
- 격리 환경에서 **10·20·40명 혼합 사용 시나리오**의 재시도 및 사용자 상태 분리를 확인했습니다. 실제 운영에서 동일한 수의 GPT 질문에 동시 응답한다는 뜻은 아닙니다.

## 공개 정보의 범위와 한계

무농사는 **공식 공고를 그대로 복제하거나 신청 자격을 최종 판정하는 서비스가 아니라, 확인 가능한 근거를 바탕으로 자료 탐색과 다음 행동을 돕는 서비스**입니다.

- **자격 비교:** 26개 공고의 41개 *일부 조건*을 비교합니다. 모든 필수조건의 충족을 보증하지 않습니다.
- **신청 준비:** 35건의 안내를 연결했고, 이 중 7건에 상세 준비정보가 있습니다.
- **금융정보:** 16개 제도 중 공식 근거가 확인된 필드만 공개합니다. 금리·한도·상환·현재 접수 여부의 확인 수준은 제도별로 다릅니다.
- **수집 자료:** 공식 정보원 접근 제한이나 승인 메타데이터 불일치가 있으면 공개를 보류할 수 있습니다.
- **AI 응답:** 모델의 일반 개념 설명은 공식 모집요강이나 금융기관의 최종 심사 결과를 대신하지 않습니다.

이 한계를 숨기지 않고 안내하는 것이 프로젝트의 핵심 설계 원칙입니다.

## 기술 구성

| 영역 | 기술·구성 |
| --- | --- |
| 프런트엔드 | HTML · CSS · JavaScript |
| 상담 | Python API · 규칙 기반 탐색·비교 · OpenAI API |
| 자료 처리 | Python 수집·검토 스크립트 · JSON · 서버 운영 DB |
| 배포 | AWS EC2 · Docker · Nginx · HTTPS |
| 협업·버전 관리 | Git · GitHub |

```text
공식 기관의 지원사업·금융·재배정보
                  │
                  ▼
         수집 및 변경 사항 확인
                  │
                  ▼
          근거 검토·공개 승인
                  │
                  ▼
            승인된 자료
             ├──────────────→ 웹 화면
             └──────────────→ Python 상담 API
                                ├─ 규칙 기반 탐색·조건 비교
                                └─ 필요한 경우 OpenAI API
```

운영 DB·비공개 승인 자료·수집 작업·상담 API 설정은 정적 웹 자원과 분리되어 있습니다. **이 저장소의 Docker 이미지만으로 실제 운영 서비스 전체가 자동 재현되는 것은 아닙니다.**

## 로컬에서 웹 화면 실행

저장소 루트에서 정적 웹 이미지를 빌드할 수 있습니다.

```bash
docker build -t munongsa:local .
docker run --rm -d --name munongsa -p 127.0.0.1:8080:80 munongsa:local
```

브라우저에서 **http://localhost:8080**에 접속합니다.

종료할 때는 아래 명령을 사용합니다.

```bash
docker stop munongsa
```

이 실행 방법은 **정적 웹 화면 확인용**입니다. 실제 상담·비공개 데이터·정기 수집을 사용하려면 별도 서버 구성이 필요합니다.

관련 문서: [상담 API 배포](deploy/chatbot/README.md) · [수집기 운영](deploy/collector/README.md)
